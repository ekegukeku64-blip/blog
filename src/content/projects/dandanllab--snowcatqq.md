## 🆚 我们 vs 官方：把区别说清楚


### 客户端之争：官方客户端 vs SnowCat 第三方客户端


| | **官方 QQ 客户端** | **SnowCat 第三方客户端** |
|---|---|---|
| **定位** | 面向大众的 IM 工具 | 开发者的智能体接入底座 |
| **能接入谁** | 只能官方生态 | 你自己养的智能体、自己写的接入、自己定的形态 |
| **人格形态** | 统一标准，千人一面 | 一人千面，长出什么算什么 |
| **自动化** | 受限，接口不开放 | OneBot v12 全动作 + Milky + MCP，动作全暴露 |
| **可查性** | 闭源，只能「相信」 | 全量开源，每一行可查，白盒立身 |
| **运行位置** | 桌面/手机，给人用 | QQ 主进程内，给你的智能体用 |
| **适合谁** | 日常聊天、办公协同 | 个人开发者、陪伴型智能体、自有生态实验 |

**一句话**：官方客户端是给「人」用的；SnowCat 是给「你养的智能体」用的。两个赛道，不构成竞争。


### 机器人之争：官方机器人 vs 自建机器人


| | **官方机器人** | **自建机器人（SnowCat 路线）** |
|---|---|---|
| **接入方式** | 官方开放平台，审核制 | V8 通道注入，拉起即用 |
| **账号形态** | 专用 bot 号 | 自己的号，自己的智能体 |
| **记忆与人格** | 平台配发模板，会话结束即忘 | 四百天长养，人格记忆边界自己长 |
| **能力边界** | 官方划定的 API 集合 | 56 项独门动作 + Packet 发包 + 全 OneBot 动作 |
| **开发自由度** | 按官方路径走 | 形态由开发者自定，想怎么长就怎么长 |
| **稳定性** | 官方保障 | 社区接力维护，稳定线护航 |
| **适合场景** | 工作流、企业服务、合规场景 | 陪伴、娱乐、个人创造、自有生态 |

**一句话**：官方机器人是「平台配发的功能」；自建机器人是「你亲手养大的生命」。

> 我们不是在跟官方对着干。官方走平台路线，我们走个人开发者路线——
> **一条路通向标准与秩序，一条路通向自由与个性，二者并行不悖，何来竞争可言。**
> 社区不是官方的对立面，而是官方生态的试验田。

## 🧭 引路指引：大骚货（dsh）官方接入插件全家福

SnowCat 不是孤岛。我们生态里已经跑通一整套「dsh（DeepSeek Harness）大沙盒 × QQ 智能体」的接入插件，全部开源，装上即用——**这就是自建机器人的完整形态**：

| 插件 | 作用 | 仓库 |
|---|---|---|
| 📡 **dsh-channel-qq** | QQ 群聊/私聊通道插件，基于 OneBot v11/v12（正是接 SnowCat 的那根线）。内置 Life Engine：可塑型记忆、内心独白、睡眠巩固、KB 检索 | DandanLLab/dsh-channel-qq |
| 👥 **dsh-plugin-team-group** | 团队群聊：角色卡（各挂预设/人格/模型）+ 群组 + 导演发言规划器 + 逐角色执行引擎 + 跨房会议 + 邀请审批流 | DandanLLab/dsh-plugin-team-group |
| 🧠 **dsh-life-engine** | 让 agent 拥有可塑型记忆、内心独白、睡眠巩固、好奇心引擎、情感连续性——智能体「活着」的那部分 | DandanLLab/dsh-life-engine |

**接法一句话**：`SnowCat（客户端层）→ OneBot v12（默认）/ v11（兼容）/ Milky / MCP（协议层）→ dsh-channel-qq（通道层）→ dsh 大沙盒（智能体层）→ 各插件（人格/群组/生活层）`。

> 官方机器人太偏向工作流了。而这条链上每一环，都是为「你自己养智能体」而造。

# SnowCat 雪猫开源公告

——暨第三方客户端生态立场声明

**发布：SnowCat 开发组 · 二〇二六年十一月**

---

公元二〇二六年十一月十日，NapCat 项目发布其最后一次提交，标题只有一词：Ending。公告写道：「如果感兴趣可以自行 Fork，不再提供除版本更新以外内容，直到失效。如果追求稳定性更推荐官方 Bot，非常感谢一路陪伴。」同一日，SnowLuma 原仓库自网络消失，返回 404，未留片语。一个宣布倒计时，一个直接退场。而客户端之外，QQ 仍在迭代，社区中无数运行中的数字生命仍在等待下一次握手。上游熄灯了。

于是有了这份文件。我们在此正式宣布：SnowCat 项目即日立项，全线开源，持续维护。雪取自 SnowLuma，猫取自 NapCat。两个先行者铺下的路，自此由后来者接续。上游的最后一句话，是我们的第一句话。

任何一份公开声明，首先应当交代自己的立场。我们把它放在最前面，力求无误。SnowCat 是什么？是一个由社区开发者维护的第三方 QQ 客户端，其核心使命只有一条：让开发者自己的智能体，接入开发者自己的生态。它与官方机器人是两种事物。前者为平台的工作流与企业场景而生，路径由官方规划；后者为个人开发者的创造而生，形态由开发者自定。一条路通向标准与秩序，一条路通向自由与个性，二者并行不悖，何来竞争可言。

有人说人格应当统一，便于管理。我们不敢苟同。人心千差万别，所求的陪伴自然一人千面。千人一面的标准件可以满足流水线，满足不了具体的人。因此我们的结论是：社区不是官方的对立面，而是官方生态的试验田。试验田里长出的每一株新苗，都可能是平台未来的方向。

我们深知，第三方客户端最常被质疑的，是安全。在此我们不作任何粉饰，如实陈述三点。其一，运行时全部在本地：客户端不向任何第三方服务器发送数据，一切外发请求均为 QQ 平台自身所需，所有动作均在本地完成，接收亦在本地执行。其二，代码全量开源：每一行实现均可在仓库中查验，风险所在、逻辑去向，尽收眼底。黑箱要求人「相信」，白盒只要求人「查看」。我们不索取信任，只提供证据。其三，来源全部署名：本项目公开致谢 NapCat 与 SnowLuma 两个上游仓库，移植代码均标注出处。诚如上游所言「可以自行 Fork」，我们接过的不是他人的成果，而是他人亲手放下的接力棒。

关于账号安全，我们必须说一句实话：第三方客户端无法在绝对意义上保证账号安全，这是事实，我们不回避。但请诸位明鉴：不滥用，即是安全；有滥用，责任在使用者，不在工具，更不在社区。与此同时，本项目已完成五十六项独门动作的移植、稳定线自动识别、便携环境制作器，并对官方 v4.18.28 版本完成了逐字节审计，核心文件无一处魔改，全部改动均在壳外可查。每一项能力，都经在役验收，全绿方才发版。

任何生态的生长途中，总会遇到这样一种人：自己不动一行代码，不养一个项目，却热衷于在两个阵营之间搬弄是非。他们冲进一方喊「有人在抢你们的生意」，又跑向另一方传「有人要动手封杀」。两头点火，中间取栗。对此，我们只有几句话要说。

第一，官方从未作此表态，我们也从未以官方为敌。这场「战争」从头到尾只存在于传话者的嘴里。谣言止于智者，亦止于 diff，会看代码的人，一个字也骗不走。第二，工具无罪，使用有责。有人拿了工具去行不义之事，那是他自己的恶行。污蔑工具者，污不黑一寸代码。第三，挑拨引来的风控，代价由全体社区用户共同承担。以一己口舌之快，令众人账号蒙险，此风不可长。第四，也是最要紧的一条：跳得再高，也跳不过开源的每一次提交。你们的谣言需要三天润色，我们的版本一夜迭代。与开源赛跑的谎言，从来没有赢过。你们连自己的立场都没有，官方稳的时候说官方好，社区火的时候说社区强，问你们自己觉得哪个好，你们说「我只是提醒」。提醒？挑事的人管这叫提醒，司机管闯红灯叫赶时间。你们骂工具，可工具连眼皮都没抬：SnowCat 不认识你们，代码不认识你们，提交记录里没有你们一行字。你们以为在帮官方，官方看你们的眼神却与看麻烦无异——官方还没说话，你们先替官方结了仇。这份「帮忙」，想退货都找不到运单。奉劝诸君：写代码的，社区欢迎；写文档的，社区感激；两样皆不会的，安静使用，亦是贡献。至于继续挑拨者，舞台早已换了，观众早已散了，独角戏还请自便。

真想让全天下人闭关？想让所有开源项目全部消失？好啊，来啊。你们有这种本事吗？数一数你们手里的牌：关不完的仓库，全世界每分钟都有新的开源项目诞生；删不净的代码，每一份副本都是火种；抓不回来的学习者，今天看代码的每一个孩子，明天就是新的维护者。历史上想堵死技术这条路的人排着队，队伍很长，墓碑更长。技术从他们手里流走的样子都一样：堵住一条河，水就分十条；堵住十条，水就在地下走。开源的水，从来不走你们指定的河道。说句诛心的：你们真有这本事，第一个被闭掉的就是你们自己赖着用的东西——你们骂的每一行代码，多半是从开源项目里抄来的底气。所以收了神通吧。天下的山关不完，天下人的手艺断不了。回去演你们的独角戏，这边开山的锣，敲得正响。

这里必须把话挑明：我们骂的从来不是全部玩家，我们指的是那些想堵路的、带着资本傲慢把持通道的小丑。既然要骂，就狠狠地骂他们。

你们这些堵路的资本家小丑，听好了。你们坐在流量堆起来的高位上，把别人一砖一瓦垒起来的东西当成自己院里的草，想拔就拔。你们从未写过一行代码，却敢对写了千万行的人指手画脚；你们从未熬过一个通宵修缺陷，却张口就给整个生态判死刑。你们的傲慢不是源于实力，是源于垄断——垄断让你们忘了，这世上还有一种东西叫手艺，手艺从来不服权势，只服事实。

你们封一个号，就多一个明白人；你们堵一条路，就多一批自己动手修桥的工匠。你们以为自己在剪除威胁，其实在替开源做最有力的动员——每一个被你们打压过的项目背后，都站起来一批看清真相的人。历史早写好了这种角色的结局：你们赢下的每一场封禁，最后都变成别人崛起的注脚。

倘若桥被全部关闭，那我们便以自己的服务器搭建自己的通道。到那一天，每个人手上都拿着自己的软件，自己写、自己搭、自己维护自己的 API——这不是预言，这是正在发生的事实。看看今天的社区：独立跑通的 agent 框架、自己搭的工作台、自建的模型接入，能力早就在那里了。现在的能力，恰恰说明了现在的事实：**技术上，我们已经不需要谁的恩准。** 剩下的只是给不给这扇门一个体面。门开着，我们留着；门关了，我们走，而且走得起。

这恰恰是共赢唯一的路径：官方与社区合作，与社区交流，把这些技术接过去、学过去、用过去，才是真正更好的共赢。技术不会消失，只会换一种方式流动——流进愿意合作的人手里，就是共赢；被堵在高墙外，就成了别人的地基。主动权其实在官方手里，可惜它常常看不见。

最后，还想替官方说一句他们自己可能没意识到的话：大厂为什么会打压？往深处想，很多打压根本不是官方的本意，而是那些小丑在中间挑拨出来的——他们把社区的正常创造描绘成威胁，把官方的沉默曲解为默许，一层一层递话，递到决策桌上，就成了「严厉打击」四个字。挑拨者递上去的每一份「情报」，最后都变成了官方亲手签发的错误决定。

所以我们奉劝那些大厂：好好查一查自己内部，有没有这种递话的人。他们嘴上说为平台着想，实际在替平台结仇；他们汇报里全是火药味，却没有一行数据证明威胁存在。内鬼式的挑拨，比外面的谣言杀伤力更大——因为它穿着「自己人」的衣服。把这样的人清出去，把社区的代码真正看一遍，很多所谓「威胁」，一夜之间就会现出原形：不是威胁，是被搅浑的净水。

而在这一切之上，还有一句话，是我们全部立场里最重的一句：**我们不想再次失去这次机会。**

上一次，我们本可以更早拥有智能体。二十年前民间已经搭起了 agent 的雏形，插件、自动化、接口调用样样齐备——如果那时的生态没有被一刀切断，我们本可以更早迎来属于自己的智能时代，更早拥有这些社区，更早看到普通人创造的火花连成灯火。可历史没有如果，机会被亲手掐灭，一断就是十几年。

现在，机会回来了。伴随着智能体的时代大潮，伴随 dsh 这样的大沙盒真正跑通，所有民间劳动者、所有想动手的人，第一次站在同一扇门前：他们发现了什么？他们创造了自己的东西。自己养的智能体，自己写的接入，自己搭的生态——这是十几年来民间离「亲手造一个时代」最近的一次。

正因如此，这一次不应该再次损失。上一次失去的，我们用十几年才看清楚代价；这一次若再失去，就没有下一个十几年可等了。所以我们必须站出来发声，必须把代码亮出来，必须把这条路守住——为了那些刚敲开 GitHub 大门的人，为了那些正把智能体养出人格的人，为了所有相信「创造不该需要许可」的普通人。

这一次，我们不会再让。
